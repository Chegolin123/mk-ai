# Архитектура

Документ описывает, как устроена игра изнутри: среда, вектор наблюдений,
пространство действий, разрешение ударов, политика и алгоритм обучения.
Всё это живёт в одном файле [`../game.py`](../game.py) — специально, чтобы
эксперимент можно было прочитать целиком за один заход.

```
            ┌──────────────────────────────────────────────┐
            │                Fight (среда)                 │
            │  физика 60 Гц · удары · награды · таймер     │
            └───────────────┬──────────────────────────────┘
                            │ obs (18) каждые 4 кадра
                            ▼
            ┌──────────────────────────────────────────────┐
            │      ActorCritic (одна сеть на двоих)        │
            │   18 → 128 → 128 → 7 actions + value         │
            └───────────────┬──────────────────────────────┘
                            │ action (7) / value
                            ▼
            ┌──────────────────────────────────────────────┐
            │   Trainer (A2C, PyTorch, CUDA)               │
            │  после эпизода: returns → advantage → шаг    │
            └───────────────┬──────────────────────────────┘
                            │ каждые 10 эпизодов
                            ▼
                    models/policy.pt
```

---

## 1. Мир и шаг симуляции

| Параметр | Значение | Где |
|---|---|---|
| Размер арены | 1280 × 720, пол на `y = 610` | `W`, `H`, `GROUND_Y` |
| Частота физики | 60 Гц | `FPS` |
| Частота решений | 15 Гц (каждые 4 кадра) | `DECISION_EVERY` |
| Длительность боя | 20 с = 1200 кадров | `MAX_FRAMES` |
| Стартовая дистанция | 560 и 720 px (160 px друг от друга) | `Fight.__init__` |
| Гравитация / прыжок | `0.78` px/кадр², `-14.0` px/кадр | `GRAVITY`, `JUMP_VY` |
| Скорость шага | 4.4 px/кадр | `SPEED_FORWARD` |
| Минимальная дистанция | 56 px (бойцы не проходят друг сквозь друга) | `Fight.separate` |

Один кадр (`Fight.step`) делает ровно это:

```python
if frame % 4 == 0:  decide(p1); decide(p2)   # сеть спрашивает обоих
apply_action(p1);   apply_action(p2)         # намерения → скорости/атаки
physics(p1);        physics(p2)              # гравитация, движение
separate()                                   # расталкивание
resolve_hits()                               # попадания и урон
shaping();          idle_penalty()           # награды
frame += 1;         check_end()              # конец боя?
```

Каждый боец — dataclass `Fighter` с состоянием (позиция, скорость, HP, таймеры
атаки/стана/кулдауна) и буферами траектории (`obs_buf`, `act_buf`, `rew_buf`,
`val_buf`), которые заполняются во время боя и используются один раз — при
обновлении весов.

### Атаки

| Атака | Длительность | Активные кадры | Кулдаун | Дистанция | Урон |
|---|---|---|---|---|---|
| Удар рукой (4) | 16 кадров | 5–9 | 26 | 96 px | 8 |
| Пинок (5) | 26 кадров | 10–16 | 40 | 128 px | 13 |

Активные кадры — окно, в котором удар может попасть. Именно поэтому пинок
сильнее и дальше, но заметно медленнее: его легче прервать контрударом.
Атака начинается только с земли и вне кулдауна, во время атаки движение
гасится (`vx *= 0.5`).

### Разрешение попаданий

`Fight.resolve_hits()` проверяет расстояние, вертикальную разницу (не больше
70 px — чтобы нельзя было попасть по прыгающему сверху) и блок:

* **блок** (`action == 6` в момент попадания): урон × 0.22, лёгкий толчок,
  атакующему `+0.5`, защитнику `-0.1`;
* **чистое попадание**: урон целиком, стан (14 кадров от руки, 20 от пинка),
  вспышка, сброс собственной атаки жертвы, отброс назад,
  атакующему `+2.0 + 0.08 × урон`, жертве `-0.6`.

Порядок обработки чередуется по чётности кадра (`self.frame % 2`), иначе боец,
которого проверяют первым, систематически выигрывал размены и self-play уезжал
в перекос (в первых прогонах — 28:12 при формально зеркальной политике).

## 2. Вектор наблюдений (18 чисел)

`s = [ ... ]`, все значения приведены к разумному масштабу:

| # | Признак | Формула |
|---|---|---|
| 0 | своё здоровье | `hp / 100` |
| 1 | здоровье противника | `o.hp / 100` |
| 2 | относительная позиция | `(o.x - x) / W` |
| 3 | дистанция | `min(1, dist / 600)` |
| 4 | разница высот | `(o.y - y) / 150` |
| 5 | я на земле | `0/1` |
| 6 | противник на земле | `0/1` |
| 7 | моя атака активна | `0/1` |
| 8 | атака противника активна | `0/1` |
| 9 | я блокирую | `0/1` |
| 10 | мой стан | `stun / 14` |
| 11 | мой кулдаун | `cooldown / 40` |
| 12 | дистанция удара рукой | `0/1` |
| 13 | дистанция пинка | `0/1` |
| 14 | остаток времени | `(MAX_FRAMES - frame) / MAX_FRAMES` |
| 15 | время с моего последнего удара | `min(1, t / 120)` |
| 16 | разница скоростей | `(vx - o.vx) / 10` |
| 17 | разница здоровья | `(hp - o.hp) / 100` |

Никаких картинок и свёрточных сетей: состояние полностью описывается этими
числами, поэтому обучение сходится за минуты, а не за часы.

## 3. Пространство действий (7)

| # | Действие | Поведение |
|---|---|---|
| 0 | стоять | скорость затухает (`vx *= 0.6`) |
| 1 | назад | `-facing × 4.4 × 0.78` |
| 2 | вперёд | `facing × 4.4` |
| 3 | прыжок | `vy = -14`, импульс вперёд |
| 4 | удар рукой | быстрый, короткий, слабый |
| 5 | пинок | медленный, дальний, сильный |
| 6 | блок | только на земле, держится, пока действие выбрано |

Действие удерживается 4 кадра (до следующего решения) — это делает поведение
«плавным» и снижает размер траектории.

## 4. Политика

```python
class ActorCritic(nn.Module):
    body   = Linear(18, 128) → Tanh → Linear(128, 128) → Tanh
    actor  = Linear(128, 7)      # логиты действий
    critic = Linear(128, 1)      # оценка V(s)
```

≈ 20 тысяч параметров. Инициализация: ортогональная, `gain = sqrt(2)` для тела,
`0.01` для actor (стартуем почти равномерно, чтобы исследовать все действия)
и `1.0` для critic.

Выбор действия — сэмплирование из `Categorical(logits)`, поэтому политика
всегда стохастична: исследует сама, без ε-greedy.

### Self-play

Одна и та же сеть управляет обоими бойцами. Это даёт сразу два эффекта:
противник всегда «на уровне» агента (не надо писать бота), и количество опыта
удваивается. Побочный эффект — счёт побед между ALEX-1 и ALEX-2 не является
метрикой мастерства; смотреть надо на удары за бой, долю простоев и долю
ничьих.

## 5. Обучение (A2C после каждого эпизода)

`Trainer.learn(fight)` вызывается сразу после конца боя.

1. **Возвраты.** Для каждого бойца считается дисконтированная сумма наград его
   собственной траектории:

   ```
   G_t = r_t + γ · G_{t+1},   γ = 0.995
   ```

   `γ = 0.995` при 15 решениях в секунду даёт горизонт ≈ 13 секунд — примерно
   длина боя, так что победа «дотягивается» до ранних действий.
2. **Advantage.** `A_t = G_t − V(s_t)`, нормируется по батчу
   (`(A − mean) / (std + 1e-8)`).
3. **Лосс.**

   ```
   L = −mean(logπ(a|s) · A) + 0.1 · MSE(V(s), G) − 0.02 · H(π)
   ```

   Энтропийный бонус не даёт политике схлопнуться в одно действие на первых
   сотнях эпизодов.
4. **Шаг.** Adam, `lr = 5e-4`, 2 эпохи по всему эпизоду, мини-батчи по 512,
   клиппинг нормы градиента `1.0`.
5. **Сохранение.** Каждые 10 эпизодов и при выходе — `models/policy.pt`
   (веса + состояние оптимизатора + номер эпизода + история).

Почему после каждого эпизода, а не раз в N: эпизод короткий (≤ 1200 кадров,
до 300 решений на бойца), обновление занимает доли секунды на GPU, зато
счётчик итераций на экране действительно соответствует числу обновлений весов —
и видно, как поведение меняется буквально на глазах.

## 6. Рендер

`Renderer` (pygame, 60 fps) рисует всё процедурно, без внешних ассетов:

* фон собирается один раз в `Surface`: градиент неба, луна, горы, каменный пол;
* бойцы рисуются из линий и кругов: ноги, торс, руки, голова, повязка, глаз;
  позы считаются от таймеров атаки (замах → выпад → возврат) и фазы шага;
* вспышки ударов, искры в точке контакта, полоски HP, HUD с итерацией,
  наградами и историей исходов;
* шрифты — системные (`segoeui`), кириллица поддерживается.

Позы не анимированы спрайтами: `draw_fighter` вычисляет положение конечностей
из состояния бойца, поэтому удар всегда совпадает с активными кадрами, а
блок — с реальным флагом `blocking`.

## 7. Режимы запуска

| Режим | Что делает |
|---|---|
| оконный (`game.py`) | рендер + обучение, управление с клавиатуры |
| `--headless` | только симуляция и обучение, без окна и SDL |
| `tools/capture.py` | SDL dummy: рендер в память → PNG/GIF для документации |

Headless и оконный режимы используют один и тот же `Fight` и `Trainer`, поэтому
чекпоинт переносим между ними: можно сутки учить в консоли, а потом открыть
окно и посмотреть, что получилось.
